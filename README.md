# mangekyo（萬花筒）

[English](README.en.md) ｜ 繁體中文

給 AI agent 用的技能：把日常的描述連到既有的專業知識。你觀察到一件事、遇到一個問題，或想做成一件事，但不知道它在專業裡叫什麼，所以搜尋不到別人做過的研究和解法。這個技能幫你找到名字、文獻和別的領域的解法，並分清楚哪些查證過、哪些只是相近。

名字取自《火影忍者》的「萬花筒寫輪眼」（Mangekyō Sharingan）。寫輪眼看穿招式的結構、看破幻術、拷貝別人的忍術，但血繼限界拷貝不了；這個技能做的是把描述看成機制、查證來源、借其他領域的解法，並寫明哪些條件不同不能照搬。萬花筒本身也是這個意思：同樣的碎片轉一下是另一個圖案，同一件事換一個領域看是另一個名字。

它是橫向的連結，不替你做決定。要把題目變成方向和計畫，用 [ryoiki-tenkai（領域展開）](https://github.com/ailazytech/ryoiki-tenkai)；這份的結果可以當它的已知背景。

## 它做什麼

| 步驟 | 內容 |
|---|---|
| 0. 確認理解，改寫成機制 | 確認理解；判斷是現象、問題還是成果；把描述去掉表面細節，改寫成「誰、在什麼限制下、想達成什麼、卡在哪裡」 |
| 1. 專業名稱 | 2–3 個不同領域的候選名稱（中英文、定義、哪裡對得上、哪裡對不上），用搜尋驗證貼不貼切；沒有對應的名稱就直接說 |
| 2. 理論與研究 | 分成直接相關的研究、可參考的理論、只有相似性的類比；每項寫適用條件、限制，以及有沒有被複製或推翻 |
| 3. 其他領域的解法 | 那個領域怎麼稱呼這個問題、怎麼處理、可以借什麼、哪些條件不同不能照搬 |
| 4. 收斂 | 最值得記住的詞彙、理論、跨領域方法，中英文關鍵字，一個小實驗，還沒查證的清單 |

規則重點：先查再寫；每一項標〔已查證〕〔憑記憶〕〔推論〕，沒開過的連結不附；不編造論文、數據或網址；不把自己取的說法當公認術語；每一步 2–4 項，寧可少而深。

## 四種用法

| 你說 | agent 會做 |
|---|---|
| 一段描述＋「萬花筒」「概念挖掘」「這有沒有專業名稱」「別的領域怎麼解」 | 跑完整流程（第 0–4 步），在對話裡回覆 |
| 「這叫什麼」「快速」 | 只給機制、候選名稱和關鍵字 |
| 「給我 prompt」 | 給 `prompt.md` 的內容，讓你貼給別的模型或 agent |
| 「存檔」 | 跑完整流程，寫成 `docs/concept-<短名>-<日期>.md` |

## 安裝

### Claude Code

把這個資料夾放到 `~/.claude/skills/mangekyo`，重開 session。

### 其他 agent 或模型

支援 `SKILL.md` 的 agent：把資料夾放到它的技能目錄。不支援的：直接貼 `prompt.md` 裡的完整版或精簡版 prompt。

## 檔案

- `SKILL.md`：給 agent 讀的技能說明（步驟、規則、輸出格式、怎麼接到領域展開）
- `prompt.md`：可以直接貼上的 prompt（完整版、精簡版）

兩個檔案裡的步驟是同一份，改其中一個時另一個要跟著改。
